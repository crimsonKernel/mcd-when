# 麦当劳几点最便宜 (mcd-when)

把麦当劳官方 MCP 的 35 个工具按**时间**维度重新整理。
别的项目回答「买什么最便宜」, 本 Skill 回答「什么时候」。

## 前置条件

环境变量 `MCD_MCP_TOKEN`（到 open.mcd.cn 手机号登录 → 控制台 → 激活获取）。
零第三方依赖，Python 3.10+ 标准库可直接运行。

## 核心能力

| 用户意图 | 调用脚本 |
|---|---|
| 「现在去还买得到早餐吗」「此刻最便宜吃什么」 | `python src/now.py --city 上海` |
| 「查 XX 城市全天价格矩阵」 | `python src/survey_national.py --city 苏州`（约 15 秒，按档核价） |
| 「XX 城市有没有麦当劳/几点开门」 | `python src/probe_cities.py --city XX` |
| 「生成可读报告」 | `python src/render_report.py` |
| 接入 AI 客户端当 MCP Server 用 | `python src/mcp_server.py`（配置见 `mcp-when-config.example.json`） |

路径相对本仓库根（`mcd-when/`）。

## 三种用法，回答三类不同的问题

| 层 | 谁采数据 | 能回答 | 门槛 |
|---|---|---|---|
| 静态页 `dist/report.html` | 我们（388 城快照） | 横向问题：全国哪最便宜、我的城市排第几、**¥20 能吃到什么** | 零，双击即开 |
| MCP Server `src/mcp_server.py` | 我们（同一份快照） | 同上，但由 AI 客户端用自然语言问 | 零 Token，纯本地 |
| 实时脚本 `src/now.py` 等 | 用户自己的 Token | 个性问题：我这店此刻买得到什么 | 需 Token + Python |

「¥20 能吃到什么」三层都能答，且答案逐分一致：算法只有一份实现
（`src/combo.py`），MCP 工具与静态页共用。静态页用的是
`src/combo_precompute.py` 预算阶梯预计算的结果（`data/combos.json`），
因为全量菜单有 5.6 MB，塞进单文件 HTML 不现实。

**为什么快照能代表"麦当劳的价格"**：实测跨 ~20 小时对比 4664 个同城同商品同时段价格点，
剔除采集 bug 后 96.8% 完全一致；真实变化集中在促销价（如麦咖啡冰奶铁中杯 ¥13.90→¥21.00）。
所以「时段结构 + 全国横向比价」这类结论稳定，但页面与 Server 都必须标注采集时间
（`data_freshness` 工具就是干这个的）。

## 关键接口事实（真机验证，别再猜）

- **渠道只有 3 类**：到店自提 `beType=1,orderType=1`；得来速 `beType=5`；麦乐送 `beType=2,orderType=2`（需配送地址 `beCode`，本项目不采集）
- **`reservationDate` 可指定未来任意时刻**（格式 `yyyy-MM-dd HH:mm`）→ 不用等真实时间，一次循环就能跑完全天
- **价格单位是分**，`calculate-price` 返回 `totalPrice`
- **`query-meals` 只给 code 不给名字**，名称需 `query-meal-detail` 补
- **官方时段表藏在 `reservationTimeOptions[].reservationOptionText` 文本里**，需正则解析；且「今天」那份只含**尚未结束**的时段——早餐一过就消失，必须按目标日期取（见 `src/patch_periods.py` 的注释）
- 不同门店营业时间差异极大：多数 07:00–22:00，也存在 00:00–23:59 的 24 小时店（其早餐档提前至 05:14）

## 硬约束

**全链路只读。** 允许调用的工具白名单在 `survey.py` 的 `READ_ONLY_TOOLS`，
`create-order` / `auto-bind-coupons` 等写操作从机制上不可达。
所有价格一律取自 `calculate-price` 实时返回，**禁止估算、禁止凭记忆报价**。

## 已知实测结论（2026-10-21 数据，全国 31 省 / 388 城 / 36152 次核价，其中 387 城为全菜单逐商品核价）

- 菜单按 4 个官方时段整批切换，档间存在约 29 分钟「菜单真空带」（早餐已收、午餐未开）
- 门店开门时刻 ≠ 可点单时刻（07:00 营业但 07:14 才开档）
- **同一商品在一天内价格恒定**；真正的变量是**可售性、时段专属套餐、渠道价差**——
  所以「按档核价」就能覆盖全国，不必逐时刻地毯式轰炸
- 早餐开档时间全国差 4 小时：东北/西北 05:14，华北 07:14，重庆 08:14；
  24 座城市的门店没有早餐档
- 363 座城市早餐档有正餐地板价；其中可与午餐对比的 361 座**全部早餐更便宜**
  （中位 ¥9.90 vs 午餐 ¥13.50），没有例外；24 座城市压根没有早餐档
- 修正记录：早期"20 座城市早餐更贵"是分类 bug（把派/薯条/热巧克力算成了正餐），
  词表重写 + `src/reclassify.py` 本地重算后该结论消失
- **「预算内怎么点最饱」的答案有地域差异**：¥20 午餐档全国收敛出 10 种搭配，
  多数城市是「圆筒 ¥5 + 随心配 ¥13.90」，但拉萨/三亚只有 ¥15.50 的牛肉堡
  （当地圆筒更贵或未上架）——所以这功能必须按城市算，不能给一个全国通用答案
- 得来速价差是分商品**双向**的（有的加价，有的反而便宜）
- 部分门店返回 600056「不支持预约取餐」，采集时需要按候选门店列表重试
